# 工作流模板用户指南

工作流模板用于复用已经验证过的协作流程。用户可以把现有工作流另存为带版本的模板，也可以从内置、个人或团队模板快速创建一份独立的新工作流。

模板保存的是流程结构、参数定义和依赖声明。通过模板创建后，ACEHarness 会生成普通的工作流 YAML；后续模板升级不会修改已经创建的工作流。

## 功能入口

进入 ACEHarness 的“工作流”页面，可以看到三个页签：

- **工作流列表**：查看、编辑和运行已有工作流，也可以将工作流另存为模板。
- **模板库**：浏览模板、查看版本和流程结构，并通过模板创建工作流。
- **草稿**：继续维护尚未发布的工作流草稿。

## 通过模板创建工作流

### 1. 选择模板

1. 进入“工作流”页面。
2. 切换到“模板库”。
3. 使用搜索框，或按分类、模式、来源筛选模板。
4. 点击模板卡片上的“查看模板”。

模板来源分为：

- **内置**：随 ACEHarness 发布，只读，所有用户可用。
- **个人**：由当前用户保存，仅创建者和管理员可见。
- **团队**：由用户保存并设置为“团队公开”，其他已登录用户也可以使用。

模板卡片默认展示最新版本。模板存在多个版本时，可以在详情窗口顶部切换版本。

### 2. 检查模板详情

模板详情包含：

- 工作流模式：状态机或阶段模式。
- 状态或阶段的执行顺序与步骤数量。
- 需要填写的参数数量。
- 依赖的 Agent。
- 是否包含步骤预命令。

如果模板提示包含预命令，建议在创建后先进入设计工作台检查命令内容，再运行工作流。

### 3. 填写实例参数

点击“使用模板”，填写“从模板新建工作流”表单。

| 字段              | 说明                                                                          |
| ----------------- | ----------------------------------------------------------------------------- |
| 配置文件名        | 必须以 `.yaml` 结尾，只能包含字母、数字、下划线和连字符；不能与现有文件重名。 |
| 工作流名称        | 新工作流在列表和工作台中的显示名称。                                          |
| 工作流描述        | 对当前工作流用途的简要说明。                                                  |
| 工作目录          | 工作流实际操作的项目绝对路径。                                                |
| 工作区模式        | “原目录执行”直接使用所选目录；“隔离副本”使用独立副本执行。                    |
| 本次需求/问题描述 | 当前实例要完成的目标、约束或问题信息。                                        |

模板可以定义字符串、多行文本、目录、选项、布尔值和数字等参数，页面会自动生成对应控件。带红色星号的参数必须填写。

### 4. 处理缺失 Agent

如果本机缺少模板声明的 Agent，创建窗口会显示“替换缺失 Agent”：

1. 为每个缺失 Agent 选择本机已有的替代 Agent。
2. Supervisor 只能替换为 Supervisor 类型的 Agent。
3. 普通执行 Agent 只能替换为非 Supervisor Agent。
4. 所有缺失 Agent 完成映射后，“创建工作流”按钮才可用。

如果缺少 Skill、MCP Server 或子工作流，需要先在 ACEHarness 中完成对应配置，再刷新模板库并重新创建。

### 5. 创建并检查工作流

点击“创建工作流”后，ACEHarness 会：

1. 校验参数类型和必填项。
2. 将参数写入模板绑定的工作流字段。
3. 应用 Agent 替换关系。
4. 校验工作流结构及 Agent、Skill、MCP Server、子工作流依赖。
5. 将新配置保存为独立的工作流 YAML。
6. 记录模板来源、模板 ID、版本和内容摘要。
7. 返回工作流列表并打开新工作流的设计工作台。

建议在首次运行前检查工作目录、需求文本、Agent 分工、预命令和结束条件。

## 将现有工作流另存为模板

### 1. 打开保存入口

1. 进入“工作流列表”。
2. 找到要复用的工作流。
3. 在行操作菜单中选择“另存为模板”，或者点击该行的模板保存图标。

### 2. 填写模板信息

| 字段     | 规则与建议                                                                             |
| -------- | -------------------------------------------------------------------------------------- |
| 模板 ID  | 使用小写字母、数字和连字符，例如 `release-review`；同一模板的后续版本继续使用相同 ID。 |
| 版本     | 使用语义化版本，例如 `1.0.0`、`1.1.0` 或 `2.0.0-beta.1`。                              |
| 模板名称 | 面向使用者的名称，说明模板解决什么问题。                                               |
| 描述     | 说明适用场景、主要产出和使用限制。                                                     |
| 分类     | 用于模板库筛选，例如“软件研发”“评审”“运营”。                                           |
| 可见性   | “个人”仅本人和管理员可见；“团队公开”允许其他已登录用户使用。                           |
| 标签     | 使用中文或英文逗号分隔，最多 12 个。                                                   |

首次保存建议使用 `1.0.0`。同一个模板 ID 和版本不能覆盖；修改模板后需要保存为新版本。

版本建议：

- 修正文案、提示或不影响主要流程的内容：递增补丁版本，例如 `1.0.0` → `1.0.1`。
- 增加参数、步骤或兼容能力：递增次版本，例如 `1.0.0` → `1.1.0`。
- 调整流程模式、关键状态或产生不兼容行为：递增主版本，例如 `1.0.0` → `2.0.0`。

### 3. ACEHarness 自动处理的内容

另存模板时，ACEHarness 会先校验源工作流，并自动转换为可移植配置：

- 清空当前项目绝对路径和本次需求。
- 删除代码库扫描结果等项目特定上下文。
- 清空 SQLite 配置中的绝对数据库路径。
- 删除 Spec 任务的运行时绑定。
- 自动提取 Agent、Skill、MCP Server 和子工作流依赖。
- 自动生成工作流名称、描述、工作目录、工作区模式和需求参数。

源工作流不会被修改。模板保存完成后，页面会自动切换到“模板库”。

## 内置模板

当前版本提供三个内置模板：

| 模板           | 模式     | 适用场景                                                     |
| -------------- | -------- | ------------------------------------------------------------ |
| 通用红蓝评审   | 状态机   | 通过方案、执行和验收三轮红蓝对抗，形成可追溯的交付结论。     |
| 软件交付       | 阶段模式 | 对范围清晰的软件需求依次完成设计、实现、测试和交付整理。     |
| 缺陷定位与修复 | 状态机   | 从稳定复现开始，经根因分析、修复评审和回归验证完成问题闭环。 |

内置模板是只读基线。需要定制时，先通过模板创建工作流，在设计工作台完成修改，再把修改后的工作流另存为个人或团队模板。

## 模板版本与实例的关系

- 每个模板版本都是不可覆盖的独立包。
- 模板库卡片展示最新版本，详情页可以切换历史版本。
- 从模板创建的工作流是独立副本，不会引用模板文件运行。
- 发布新模板版本不会自动升级或修改已有工作流。
- 需要采用新版本时，应从该版本重新创建工作流，再按需迁移实例数据。

## 存储位置

默认情况下：

```text
内置模板：<ACEHarness 安装目录>/templates/workflows
用户模板：~/.aceharness/templates/workflows
工作流实例：~/.aceharness/configs
```

设置 `ACE_HOME` 后，用户模板和工作流实例会改到：

```text
$ACE_HOME/templates/workflows
$ACE_HOME/configs
```

用户模板采用以下目录结构：

```text
<template-id>/<version>/
  manifest.yaml
  workflow.yaml
```

`.metadata.json` 保存模板创建者、可见性和创建时间，由 ACEHarness 管理，不建议手工修改。

## 常见问题

### 提示“该模板版本已存在”

模板版本不可覆盖。保留相同模板 ID，将版本号递增后重新保存。

### 提示“工作流文件已存在”

修改“配置文件名”，或者先确认现有工作流是否仍需保留。系统不会覆盖已有工作流文件。

### 提示“模板依赖未就绪”

- 缺失 Agent：返回创建窗口完成 Agent 替换。
- 缺失 Skill：先安装或启用相应 Skill。
- 缺失 MCP Server：先完成 MCP Server 配置。
- 缺失子工作流：先创建或恢复被引用的工作流配置。

完成依赖配置后，刷新模板库再重试。

### 提示“源工作流配置无效”或“无法转换为可移植模板”

先在设计工作台打开源工作流并修复配置校验问题。重点检查必填字段、状态转换、Agent 引用、子工作流引用以及路径类配置。

### 模板库看不到刚保存的模板

- 确认搜索和来源筛选条件没有将模板过滤掉。
- 点击模板库右上角的刷新按钮。
- “个人”模板仅创建者和管理员可见。
- 如果使用了自定义 `ACE_HOME`，确认当前服务进程使用的是同一个目录。

### 创建按钮不可用

检查是否仍有必填参数未填写，或是否存在尚未选择替代项的缺失 Agent。

## 面向维护者的模板包扩展

维护者可以在 `templates/workflows/<template-id>/<version>` 下增加内置模板包。每个包包含：

- `manifest.yaml`：模板标识、版本、参数、兼容范围和依赖。
- `workflow.yaml`：可移植的阶段模式或状态机工作流。

`manifest.yaml` 使用：

```yaml
apiVersion: aceharness.io/v1alpha1
kind: WorkflowTemplate
metadata:
  id: example-template
  version: 1.0.0
  name: 示例模板
  description: 示例用途
  category: 示例
  tags: [示例]
spec:
  entrypoint: workflow.yaml
  mode: phase-based
  compatibility:
    aceharness: ">=1.0.0-rc.8 <2.0.0"
  parameters:
    - id: projectRoot
      label: 工作目录
      type: directory
      bind: /context/projectRoot
      required: true
  dependencies:
    agents: []
    skills: []
    mcpServers: []
    subworkflows: []
```

参数的 `bind` 使用 JSON Pointer 指向 `workflow.yaml` 中要替换的字段。支持的参数类型为 `string`、`text`、`directory`、`enum`、`boolean` 和 `number`。

模板注册中心会拒绝以下包：

- 目录名与 `metadata.id` 或 `metadata.version` 不一致。
- ID、版本或参数定义不符合约束。
- 参数 ID 或绑定路径重复。
- `manifest.yaml` 声明的模式与 `workflow.yaml` 不一致。
- 工作流未通过可移植模式校验。
- 模板目录使用符号链接。

更多包格式说明见 [`templates/workflows/README.md`](../templates/workflows/README.md)。
