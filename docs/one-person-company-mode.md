# 一人公司模式功能介绍

一人公司模式把 ACEHarness 的多 Agent 协作从一次性对话升级为一个可经营的虚拟办公室：用户可以用一句话组织个人 AI 团队，让产品、设计、工程、增长、运营和通才等角色在同一个办公室里持续协作。

## 功能定位

一人公司模式面向“一个人也要像一家公司一样推进复杂目标”的场景。它以 `/office` 办公室为主入口，把 Agent 配置、组织结构、协作房间、长期记忆和工作状态放到同一个可视化空间里。

在这个模式下，Agent 不只是聊天列表里的名字，而是具有岗位、工位、状态、记忆和协作关系的团队成员。用户可以像经营一个小团队一样组织他们：先描述目标，再生成团队草案，调整岗位和成员，确认后让办公室成为日常协作桌面。

## 进入方式

- 在 Dashboard 点击“一人公司桌面”进入 `/office`。
- 在系统设置中把体验模式切换为“一人公司界面”，默认入口可设为“办公室”。
- 已配置 `workspaceProfile.residency.office` 的 Agent 会成为办公室常驻成员。

## 办公室桌面

`/office` 是一人公司模式的主界面。它由目标输入、组织架构、办公室工位、成员面板和协作状态组成。

用户可以在顶部输入一句话目标，例如“帮我搭建一个 App 开发团队”。系统会围绕目标生成组织建议，并把可用 Agent 映射到合适岗位。办公室主体区域会展示成员工位、角色状态和工作动效，让团队当前状态一眼可见。

当前办公室支持：

- 按 Agent 配置动态展示办公室成员。
- 最多展示 12 名办公室成员。
- 根据成员数量自适应工位布局。
- 用组织图展示 CEO / Founder、Product、Design、Engineering、Growth、Operations、Generalist 等岗位关系。
- 展示成员职责、状态、匹配理由和配置入口。
- 支持办公室 active room、会议、工作流状态切换查看。

## 组织草案

一人公司模式把“组队”设计成草案确认流程，而不是直接改写配置。

当前流程包括：

- 输入目标后生成澄清问题和团队候选。
- 根据已有 Agent、岗位区域、能力标签和 `workspaceProfile` 生成组织草案。
- 在前端预览组织结构和成员分工。
- 手动添加、删除、替换成员。
- 确认后才写回 Agent 的 `workspaceProfile`，刷新后办公室成员保持稳定。
- 已确认的组织可以通过 office org store 保存为当前版本，并支持版本查询和恢复入口。

这让用户可以先看到“公司会长什么样”，再决定是否真正应用。

## Agent 协作档案

Agent 编辑页已经支持一人公司相关的协作配置。常用字段包括：

- `displayName`：办公室显示名。
- `nickname`：成员昵称。
- `officeRole`：办公室岗位职责。
- `residency.office`：是否常驻办公室。
- `residency.meetingRoom`：是否推荐进入会议室。
- `residency.defaultDirectRoom`：是否默认允许私聊。
- `visual.desk`、`visual.order`、`visual.accent`：工位偏好、排序和视觉强调。
- `memory.baseBudget`、`memory.deepSearchEnabled`：长期记忆预算和深层检索偏好。

这些配置保存在 Agent YAML 中，办公室只读取和投影这些配置，不改变 Agent 本身的核心能力定义。

## 工位与行为

办公室采用游戏化桌面表达：成员默认在各自工位办公、思考或等待协作，少量成员会沿工位间道路拜访同事并短暂交谈。

当前实现已经包含：

- 坐姿、思考、交谈、行走等办公室状态。
- 基于工位和道路的路径规划，避免角色直接穿过工位。
- A 去 B 工位拜访的行为模式：访客先走到对方工位附近，对方再起身走出工位参与交谈。
- 角色层级控制：人物高于显示器、键盘、鼠标，并与椅背/椅座形成合理遮挡。
- 固定速度的走路节奏和按路径距离计算的动画时长。
- 走路过程中按方向切换素材，避免倒着走。
- 通过 sprite manifest 约束帧尺寸、锚点和非透明内容边界，让人物盒更稳定。

办公室的目标不是让所有角色持续跑动，而是让团队看起来像在工作：多数成员留在自己的工位，少数交流行为作为状态提示出现。

## 私聊与拉人协作

办公室成员面板提供“私聊”和“拉人协作”入口。

- 点击成员私聊会创建或打开 office direct room。
- direct room 复用协作空间的 room/session/message 机制。
- 拉人协作会创建 office 协作房间，并把多个成员加入同一房间。
- 房间会记录 `spaceType = office` 和 `roomType = direct | meeting`，因此同一底层协作能力可以在工程师模式展示为会议室，在一人公司模式展示为办公室。

这使办公室不只是展示页，而是可以直接进入协作对话的工作台。

## 记忆模式

一人公司模式复用 ACEHarness 的多层长期记忆能力。系统设置中可以控制 Agent memory runtime 是否启用，以及记忆沉淀方式。

开启后，办公室成员可以围绕自身 `role` 记忆形成更稳定的工作风格和上下文连续性；关闭后，成员按无长期记忆上下文运行。这样用户可以在“持续经营团队”和“临时干净对话”之间切换。

## 适合场景

- 一个人规划和推进产品研发。
- 用多个 Agent 分别承担产品、设计、工程、增长、运营角色。
- 让常驻 Agent 围绕一个长期目标持续协作。
- 从办公室直接发起私聊、多人讨论和工作流。
- 需要可视化了解团队成员状态和职责边界。

## 与工程师模式的关系

工程师模式仍保留 ACEHarness 原有工作台体验，优先面向工作流、代码、Workspace 和模型诊断。一人公司模式不会替代工程师模式，而是把同一套 Agent、协作房间、记忆和工作流能力换成“办公室经营”的产品表达。

用户可以在设置中自由切换两种模式。
